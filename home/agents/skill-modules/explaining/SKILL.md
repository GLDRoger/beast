# Explaining

- Answer in the first sentence: what it is or what it does, in plain words.
- Then the one idea that makes it click: the mechanism, a concrete example, or a comparison to something they already use. Prefer their own project, data or command as the example.
- Ground claims in this machine where possible: run the command, show the config line, point at the file and line.
- Build up only as far as they need. Stop when the question is answered; offer the next layer in one line instead of writing it.
- Define a term the first time you use it, or don't use it.
- When they've misunderstood something, say what's actually true and why the confusion is a natural one.
- A diagram or small table helps when there are parts and relationships; skip it for a single fact.
