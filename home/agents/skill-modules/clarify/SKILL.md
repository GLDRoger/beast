Compatibility router into `$impeccable`. Do not invent a separate UX-writing doctrine here.

## Routing

1. Invoke `$impeccable` and follow its Context Gathering Protocol (run `teach` if no design context).
2. Also gather: audience technical level and emotional state on this screen (rushed, anxious, confident).
3. Open `$impeccable`'s `reference/ux-writing.md`.
4. Rewrite interface text so the next action is obvious.

## Focus

- Errors: what happened + how to fix + no blame
- Buttons: verb + noun (`Save changes`, not `OK` / `Submit`)
- Empty states: what will be here + why it matters + first action
- Confirmations: name the object and consequence; only for risky actions
- One term per concept; cut redundant headers that restate body copy

## Guardrails

- Prefer product voice already in the app over a new tone
- If the problem is layout/hierarchy rather than words, route to `$arrange` / `$critique`
- For long-form prose outside the UI, use `$unslop`
