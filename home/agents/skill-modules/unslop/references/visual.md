# Visual cleanup

Inspect the relevant rendered interface before claiming a visual problem. Use the product's existing workflow, audience, and brand as evidence. State the inspected surfaces and states; a screenshot of one viewport is not an exhaustive review.

## Diagnose the consequence

- **Hierarchy:** competing calls to action, equal-weight sections, gratuitous card grids, badges on every label, or decorative metrics can obscure what matters. Make the primary task and information order clearer.
- **Typography and spacing:** fix awkward wrapping, unstable alignment, arbitrary spacing, weak contrast, and headings that overpower content. Preserve an intentional type system; no font is automatically disallowed.
- **Decoration:** ask what a gradient, border, shadow, icon, illustration, or effect contributes. Remove decoration that crowds the workflow or creates a false signal, not every instance of a visual technique.
- **Copy and controls:** keep one term per concept, meaningful labels, accurate status, and obvious next actions. Replace filler and vague promises without inventing stronger claims.
- **Interaction:** keep hover, pressed, focus, disabled, loading, empty, error, and success states clear. Motion should give feedback or continuity, remain interruptible where needed, and honor reduced motion.
- **Resilience:** inspect narrow screens, long labels/content, keyboard paths, contrast, and relevant localization/overflow cases. Do not simplify away accessible names, confirmation for consequential actions, or necessary recovery states.

Rank findings by user consequence and evidence. Recommend the smallest coherent revision that resolves the problem. Do not substitute a new brand or a favored minimalist aesthetic for the user's requested cleanup.

For an authorized fix, make the changes and inspect the rendered affected states at relevant narrow/wide viewports. Preserve functionality and verify the main interaction. If rendering is unavailable, distinguish a source-based concern from a visually verified defect and say what remains unchecked.

Use the frontend workflow for major interface work and the motion workflow for substantial animation. This reference is a cleanup lens, not a compulsory redesign process.
